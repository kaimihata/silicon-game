Chip City — Greybox Spike

Build brief for the first playable proof that chip design, factory layout, and profit form one understandable loop.

1. Purpose and success hypothesis

This is not the full game. It is a small web prototype that proves a player can design a chip, see its manufacturing consequences, build a physical line, run it, observe waste and bottlenecks, and understand why the result made or lost money.

Core hypothesis: moving a chip part or changing a connection should create a factory consequence the player can observe, diagnose, and respond to. The spike succeeds only if this feels like one connected game rather than two separate calculators.

2. Scope and non-goals

In scope

  • One fixed contract for 1,000 accepted controller chips.
  • One chip board with starter parts and explicit connections.
  • One 12×8 factory floor built from an empty shell.
  • One continuous production simulation, waste, revenue, and one optional scanner upgrade.
  • Live requirement, margin, and manufacturing-profile feedback.

Explicitly out of scope

  • No campaign, rotating market, research tree, or fiscal reports.
  • No advanced materials, utilities, recycling, rework, or multiple factories.
  • No polished story, cinematic intro, complex art, or detailed semiconductor realism.
  • No freehand chip-wire routing, multiplayer, modding, or save/load requirement.

3. Player journey

  1. Read contract. The contract pays $100 per accepted chip and requires 1,000 accepted chips. It has a minimum responsiveness requirement; there is no timer, deadline, or failure state for slow play.
  2. Design chip. Select parts, place them on a 6×6 die, and create the three required connections. The design board prevents submission until responsiveness passes.
  3. Read production readiness. See live material cost, predicted process/inspection/test/package loads, expected yield, waste estimate, margin per accepted chip, and required factory machines.
  4. Build factory. Borrow if needed, purchase the required starter equipment, place it on the 12×8 floor, and connect it with transport.
  5. Run line. Component kits enter through the input bay; wafers flow through each machine; rejects go to garbage; packaged accepted chips ship and generate revenue.
  6. Learn and respond. Observe the first bottleneck. Buy a second inspection machine if desired, or return to the chip board and revise the design. Faster production means higher revenue per second, not a deadline bonus.

4. Presentation and interaction direction

The spike may use placeholder geometry, but it must feel high-tech and readable: dark navy/teal interface chrome, clean-grid chip floor plan, enclosed wafer tracks, glowing data routes, compact numerical panels, and animated flow. It should not depend on a story or rundown visual theme.

Chip design board

6×6 silicon grid; selectable parts with distinct footprints and ports; click a port then another port to make a link. Hover/drag previews show only the values affected by the pending change.

Factory board

12×8 grid; click to select a building/track, then place it. Routes visibly carry component kits, fabricated wafers, passed wafers, packaged chips, and rejects.

Readiness panel

Always show contract pass/fail, material cost, expected yield, margin per accepted chip, process/inspection/test/package loads, and a short plain-language diagnosis.

5. Shared terminology

TermDefinition
Chip partsFunctional blocks placed on the chip board: CPU, memory, display I/O, cooling/power.
ConnectionsData links placed between chip-part ports. They have traffic, distance, capacity, complexity, and reliability implications.
Manufacturing profileThe bridge from a chip design to the factory: paid component-kit cost, machine load, expected yield, waste, and packaging needs.
Factory inputsPaid component kits that correspond to the selected chip parts. They arrive at the input bay.
Production machinesProcess, inspection, test, and packaging buildings. They transform units in sequence.
RejectsFailed inspection/test units. In this spike, they go to the garbage output and never count toward the contract.

11. Build acceptance summary

  • A player can complete the full loop without consulting a hidden formula.
  • Every chip-design choice visibly changes at least one of: contract eligibility, margin, machine load, waste, or revenue per second.
  • Rejects move through a distinct physical route and never count toward the 1,000 accepted units.
  • A player can diagnose inspection as a bottleneck from the factory view and see the second scanner increase accepted-chip output.
  • The UI previews effects before commitment and confirms them after the simulated line runs.
